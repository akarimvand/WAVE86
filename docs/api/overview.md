# 🌐 استانداردهای وب‌سرویس و معماری API (API Overview)

## ۱. ساختار عمومی و قالب پاسخ‌ها (Response Envelope)

تمام وب‌سرویس‌های سامانه از یک ساختار استاندارد، قابل پیش‌بینی و یکپارچه در قالب JSON استفاده می‌کنند.

### ۱.۱. پاسخ‌های موفق (Success Response)
```json
{
  "success": true,
  "message": "پیام اختیاری موفقیت عملیات به فارسی",
  "data": { ... }, // یا کلید مستقیم مرتبط با موجودیت مانند "users", "product", ...
  "dbConnected": true
}
```

### ۱.۲. پاسخ‌های خطا (Error Response)
```json
{
  "success": false,
  "error": "شرح دقیق و کاربرپسند علت بروز خطا به زبان فارسی",
  "details": "اطلاعات اشکال‌زدایی (در صورت وجود)"
}
```

---

## ۲. استانداردهای احراز هویت و هدرهای HTTP

برای دسترسی به اندپوینت‌های محافظت‌شده، ارسال توکن JWT در هدر استاندارد `Authorization` به صورت Bearer Token الزامی است:

```http
Authorization: Bearer <JWT_TOKEN_STRING>
Content-Type: application/json
```

---

## ۳. کدهای وضعیت HTTP (HTTP Status Codes)

| کد | عنوان | کاربرد در سامانه |
| :--- | :--- | :--- |
| `200` | OK | دریافت موفق اطلاعات، به‌روزرسانی موفق یا پاسخ به کوئری‌ها |
| `201` | Created | ایجاد موفق موجودیت جدید (کاربر جدید، دوره جدید، محصول جدید، تراکنش، ...) |
| `400` | Bad Request | اعتبارسنجی ناموفق بدنه درخواست یا فقدان فیلدهای الزامی |
| `401` | Unauthorized | عدم ارسال توکن، انقضای توکن یا اشتباه بودن نام کاربری / رمز عبور |
| `403` | Forbidden | کاربر احراز هویت شده اما سطح دسترسی لازم برای عملیات را ندارد یا دسترسی غیرمجاز به حساب دیگری (IDOR) |
| `404` | Not Found | موجودیت درخواستی با شناسه مشخص‌شده در دیتابیس یافت نشد |
| `500` | Internal Server Error | خطای سرور در ارتباط با پایگاه داده یا اجرای کوئری‌ها |

## ۴. لیست میدل‌ورهای گارد و اعتبارسنجی (Guard Middlewares)

در فایل `/server/middleware.ts` میدل‌ورهای گارد زیر تعبیه شده‌اند:

1. **`authenticateJwt`:** بررسی وجود هدر Bearer و اعتبارسنجی امضای توکن با کلید مخفی سرور. شیء دیکودشده کاربر را در `req.user` قرار می‌دهد.
2. **`optionalJwt`:** استخراج توکن در صورت ارسال، بدون مسدودسازی درخواست در صورت عدم ارسال توکن.
3. **`requireRoles(allowedRoles: string[])`:** بررسی این که آیا حداقل یکی از نقش‌های موجود در `req.user.roles` با نقش‌های مجاز تعریف‌شده همخوانی دارد یا خیر.
4. **`validateRequestBody(requiredFields: string[])`:** اعتبارسنجی حضور کلیدهای ضروری در بدنه درخواست JSON ورودی و بازگرداندن خطای ۴۰۰ در صورت فقدان هر یک.
