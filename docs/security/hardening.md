# 🛡️ استحکام‌بخشی و دفاع در عمق سرور (Security Hardening)

## ۱. هدرهای امنیتی با Helmet

در فایل `/server.ts` پکیج امنیتی `helmet` فعال شده و تنظیمات امنیتی زیر را روی هدرهای HTTP اعمال می‌کند:
- **`Cross-Origin-Resource-Policy`:** تنظیم روی `cross-origin` به منظور امکان لود امن تصاویر و رسانه‌های استاتیک آپلودشده در تگ‌های `<img>` و صفحات فرانت‌اند.
- **`Content-Security-Policy (CSP)`:** مجازشمردن اجرای اسکریپت‌های درون‌برنامه‌ای، وب‌فونت‌ها و استایل‌ها بدون ایجاد رخنه امنیتی.
- **غیرفعال‌سازی هدر `X-Powered-By`:** جلوگیری از افشای استفاده از پشته فناوری Express و Node.js برای نفوذگران.

---

## ۲. کنترل نرخ درخواست (Rate Limiting)

برای پیشگیری از حملات منع سرویس (DoS)، جستجوی فراگیر (Brute-Force) در صفحه لاگین و اسکن خودکار اندپوینت‌ها:
- از پکیج `express-rate-limit` استفاده شده است.
- **محدودیت پیش‌فرض:** حداکثر ۱۰۰۰ درخواست در هر بازه زمانی ۱۵ دقیقه‌ای به ازای هر آدرس IP منحصر‌به‌فرد.
- در صورت تجاوز از این سقف، سرور با خطای HTTP 429 (Too Many Requests) پاسخ می‌دهد.

## ۳. اعتبارسنجی جادویی بایت‌های فایل (Magic Bytes File Sniffing)

تنها بررسی پسوند فایل (مانند `.png` یا `.jpg`) برای جلوگیری از آپلود شل و فایل‌های مخرب ناکافی است. در تابع `validateFileMagicBytes` واقع در `/server/middleware.ts`، امضای باینری ابتدای بافر فایل‌ها با استانداردهای جهانی تطبیق داده می‌شود:

| فرمت مجاز | امضای هدر باینری (Magic Bytes) | کاربرد |
| :--- | :--- | :--- |
| **JPEG / JPG** | `FF D8 FF` | تصاویر پروفایل، فیش‌های واریزی و عکس کالا |
| **PNG** | `89 50 4E 47 0D 0A 1A 0A` | لوگوها و تصاویر شفاف |
| **GIF** | `47 49 46 38` (`GIF8`) | انیمیشن‌ها و بنرها |
| **WEBP** | `52 49 46 46` ... `57 45 42 50` (`RIFF`...`WEBP`) | تصاویر فشرده وب |
| **PDF** | `25 50 44 46` (`%PDF`) | مدارک بیمه ورزشی و اسناد رسمی |

در صورتی که یک فایل مخرب با پسوند جعلی ارسال شود اما بایت‌های باینری آن با امضاهای فوق مطابقت نداشته باشد، سرور بلافاصله فایل را رد کرده و از دیسک حذف می‌نماید.

---

## ۴. پیشگیری از تزریق به پایگاه داده (SQL Injection Prevention)

در تمامی کوئری‌های تعبیه‌شده در `/server/mysql.ts`، `/server/repository.ts` و روترها:
- از **Prepared Statements** و کوئری‌های پارامتری در درایور `mysql2/promise` (با نماد `?`) استفاده شده است.
- هیچ‌گونه اتصال مستقیم رشته‌ها (String Concatenation) برای مقادیر ورودی کاربر در کوئری‌های SQL وجود ندارد که ریسک SQL Injection را به صفر می‌رساند.
